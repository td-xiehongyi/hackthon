# 角色目录与新增流程

日期：2026-09-26。适用于现有和后续所有角色。用户已要求统一放置素材，并为后续多个角色保留清楚的管理方式。

## 1. 从哪里开始

**唯一角色清单：[assets/characters/README.md](../assets/characters/README.md)。**

当前登记 3 个角色：粉白开衫女生、棕发绿包女生、临时测试角色。E1/E2 是同一角色的阶段，v1/v2 是素材修订版，都不另算一个角色。旧 `public/characters/student/.gitkeep` 仅为占位，不能登记成成品。

角色目录保存原件与交付记录；应用公开目录保存最小运行副本。界面是否提供角色选择、同时显示多个角色是单独的开发事项，本次目录整理没有增加这些功能。

## 2. 固定 ID、显示名与版本

- 每个角色分配一个唯一、稳定的小写英文 ID，允许数字和连字符，例如 `photo-student`、`photo-sage-student`。
- 新建前检查清单，避免重复 ID。不使用真实姓名、照片临时文件名或 `新角色最终版2` 作为 ID。
- 显示名用于阅读，可以改；固定 ID 不随衣服细修、阶段、显示名或中文名称变化。
- 后续角色的目录名与 `manifest.characterId` 统一使用固定 ID，`schemaVersion` 仍遵循原接口。
- E1、E2、E3、E4 表示制作阶段；同阶段修订用 `-v2`、`-v3`，并在角色 README 写清当前使用哪一版。不要覆盖已确认的原图。
- 阶段、版本号、批准状态不能编码到固定 ID。粉白开衫女生旧 `photo-student-e2-candidate` 已迁为 `photo-student`。

## 3. 每个角色保存什么

| 位置 | 内容 |
|---|---|
| `assets/characters/<id>/README.md` | 显示名、固定 ID、外观概要、当前阶段、当前选定版本、预览入口、确认记录、首页是否使用、未完成项、下一步 |
| `<id>/e1/` | 设计样张、修订图、裁切/锚点草案、来源、生成提示词、外观预览和审阅记录 |
| `<id>/e2/` | 动画小样、候选 manifest、逐帧锚点、动态预览、实际检查报告 |
| `<id>/e3/` | 完整素材包及接口检查记录；有真实交付时才建立 |
| `<id>/e4/` | 接入问题修订及复验记录；有真实交付时才建立 |
| `<id>/releases/<version>/` | 经确认并完成对应验收的导出快照；仅包含真实 PNG、manifest、来源/版本说明 |
| `public/characters/<id>/` | A 选定版本的运行副本，供网页加载 |

现有临时角色历史结构采用 `<id>/runtime/`，保持来源说明；其运行目录 `temp-prototype` 是明确登记的旧别名，不作为新角色命名范例。

只建立当前需要的目录；缺少动画、照片或源工程时保留缺失状态。未经需要不复制私人原照片；记录使用来源和条件即可。原图、源工程、预览、脚本和审阅截图不应随正式运行副本一起公开。

## 4. 新增一个角色

1. 检查角色总清单，选择未占用的固定 ID，并新建 `assets/characters/<id>/README.md`。
2. 在总清单添加一行，先写真实状态，例如“E1 制作中”。不把尚未存在的 PNG、manifest 或动画登记为已完成。
3. 将 E1 样张及来源保存到 `<id>/e1/`，写清照片中可见特征和设计补全，链接当前审阅版。
4. 按 [角色素材接口](04_角色素材接口.md) 完成外观审阅 → 动画小样 → 完整包 → 接入修订；每次更新角色 README 和总清单中的最新状态。
5. 完整包通过验收后，保存带版本号的导出快照。A 再将选定快照复制到 `public/characters/<id>/`，记录版本、来源路径和校验值。
6. A 配置运行目录，复核等比缩放、碰撞和遮挡，并测试 16 状态、WASD、Shift、返回及失焦暂停。完成后才能把“首页使用”和对应验收项改成“是/通过”。

状态至少区分：制作中、待审阅、外观已确认、动画小样、待接入、已接入待验收、已验收、临时测试、停用。可以用自然语言补充，不用一个“完成”掩盖所有层次。

## 5. 接入和运行副本

新角色运行目录为 `/characters/<id>`。已有 `VITE_CHARACTER_DIR` 只是在启动/构建时指定一个包，不会自动扫描清单，也不是玩家角色选择功能。

例如，将来 `photo-student` 完成正式交付、复制到运行目录且 A 已处理显示比例后，才可使用：

```powershell
$env:VITE_CHARACTER_DIR = '/characters/photo-student'
npm run dev
```

这只是未来接入示例，**当前该正式运行包不存在**。目前默认角色仍为 `/characters/temp-prototype`。

粉白开衫女生的 E2 原图尺寸为 1254 × 1254，候选比例约 0.10；当前首页调用加载器的默认比例为 1。只更换素材目录会让人物过大，须由 A 复核比例。不能将裁切尺寸直接视为碰撞体，不能向 manifest 塞入世界坐标或移动速度。

临时角色重新导入时运行既有 `tools/character/import-prototype.mjs <外部原型目录>`，工具会先写 `assets/characters/temp-prototype-blob/runtime/`，再同步当前运行副本。该外部输入目录本次未重新验证。

## 6. 多人同时制作

- 每个人维护自己角色的固定目录；不要重用别人的目录、候选 manifest 或图片名称来交付另一人。
- 新增/更新总清单前重读 README，只修改自己的那一行，保留其他人的更改。
- 正在制作或打开中的目录不随意移动；迁移前确认没有任务依赖旧位置。
- 公共加载器、地图和碰撞仍由 A 维护。素材整理或外观确认不等于授权开发下一阶段、提交、推送或发布。
- 需要共用预览布局时明确记录依赖。当前绿包女生的准备脚本复用粉白开衫女生 E1 布局，已更新为新路径。
