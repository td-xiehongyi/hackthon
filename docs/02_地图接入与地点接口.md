## 2. 所有模块共用的坐标规则

- 地图 ID 为 `csu-campus-v20`（随底图版本变化；更换底图时同步更新）；坐标系固定为 `image-pixels-top-left`。
- 原图左上角为原点，x 向右、y 向下，单位为原图像素；完整图片范围为 1041 × 1511。
- `Point` 为 `{ x: number, y: number }`，`Polygon` 为 `Point[]`。坐标必须为有限数值；落点位于图内，多边形边界可以接触图片边缘。多边形至少三个有效顶点，不自交。
- 标注数据不用屏幕坐标、百分比、经纬度或推测的现实距离。窗口变化、镜头滚动、缩放与设备像素比由 A 在渲染/输入转换处处理，不能反写标注坐标。
- 角色位置统一指脚底中心。角色脚底碰撞体及尺寸由 A 明确记录，行走、骑行和安全点使用完整脚底碰撞体检查；是否进入交互范围按脚底点判定，不要求整个碰撞体进入触发范围。角色头部或精灵外框不充当地面坐标。
- 未标定坐标使用允许的 `null` 或空集合；禁止用 `(0,0)`、截图目测坐标或虚构位置冒充待定值。测试场景使用单独的测试夹具，不写入正式地图标注。

地图缩放只影响显示，原图坐标不变。地理朝向、比例与距离压缩另行核验，不由这个二维坐标契约推定。

## 3. `MapAnnotation` 数据契约

| 字段 | 约定 |
|---|---|
| `schemaVersion` | 固定为 `1`；不兼容变更须显式升级 |
| `mapId` | 当前为 `csu-campus-v20`，与底图版本绑定 |
| `imagePath` | 运行路径 `/maps/campus-v20.png` |
| `imageSha256` | 第 1 节的完整 SHA-256；用于阻止图片变更后继续静默使用旧坐标 |
| `widthPx` / `heightPx` | 分别为 `1041` / `1511` |
| `coordinateSystem` | 固定为 `image-pixels-top-left` |
| `annotationStatus` | `pending` 或 `verified`，表示游戏标注是否完成相应核验 |
| `geographyStatus` | `pending` 或 `verified`，表示现实地理资料核验状态，与游戏标注状态独立 |
| `walkableAreas` | `PolygonArea[]`；允许通行的地面区域 |
| `collisionAreas` | `CollisionArea[]`；需要阻挡角色的区域 |
| `landmarks` | `Landmark[]`；展示、搜索和定位地标 |
| `buildings` | `Building[]`；已核实且纳入潇湘教学楼群的楼座 |
| `interactions` | 三个固定地点的交互记录；未标定时保留记录和空坐标 |
| `safePoints` | `SafePoint[]`；核验后提供出生、快速移动或返回兜底点 |
| `occluders` | `Occluder[]`；新增遮挡素材及其定位、深度信息 |

### 3.1 行走区与碰撞区

`PolygonArea` 为 `{ id, polygon }`；`CollisionArea` 在此基础上增加 `reason`，说明建筑、水体或其他阻挡原因。ID 在各自集合内唯一。

有效通行范围是行走区的并集减去碰撞区。行走区之外默认不可通行；没有标注时不能把整张图片默认开放。角色的完整脚底碰撞体须处于有效通行范围，不能只检查中心点。

道路、连接小路、桥面和入口平台按实际游戏通行意图标定；建筑、水面等按地面关系标定。屋顶轮廓不自动等于建筑落地边界，树冠也不自动等于树干碰撞体。

2026-09-26 通行规则调整：草地和操场内部开放；建筑附近、道路附近的树木可通过；窄路允许骑行。当前步行/骑行都使用 8×4 原图像素的完整脚底碰撞框。修正源、距离参数、桥面与阻挡边界见 [碰撞与通行规则](07_碰撞与通行规则.md)。树木放行是通行规则，不代表正式前景遮挡素材已经交付。

桥面需要单独核验：桥面行走区不能同时被整片水域碰撞覆盖。可将水域碰撞拆成不覆盖桥面的多个多边形；不通过“所有桥无视碰撞”的特殊规则绕开。两端接路处都应容纳脚底碰撞体。步行与骑行使用同一有效通行范围，速度变化不得导致穿透障碍。

### 3.2 地标与教学楼座

`Landmark`：

`{ id, name, campusId, anchor: Point | null, verificationStatus }`

`campusId` 使用共享声明中的校区 ID，`verificationStatus` 使用 `pending` / `verified`。`anchor` 是地图标记位置，不是功能入口或安全落点。普通地标只用于展示、搜索和目标标记，不因为存在 `anchor` 就出现进入按钮或相册入口。

`Building`：

`{ id, name, campusId: 'xiaoxiang', groupPlaceId: 'xiaoxiang_teaching_group', aliases: string[], landmarkId: string | null }`

楼座 ID 用于课程关联，别名用于已核实的名称匹配；不得用未核实的 A/B/C 座填满列表。`landmarkId` 可为空，表示已经收录该楼座，但暂未建立独立地图定位。楼座没有自己的功能面板或相册，课程筛选不会改变教学楼群相册所属地点。

该楼座集合描述潇湘统一入口的楼座映射，不能据此推导“个人课表禁止录入其他校区课程”。未匹配的课程地点仍须保留原始文字及未匹配状态，按课表契约处理。

### 3.3 三个交互地点

| 固定 `placeId` | 固定 `featureKey` | 场景功能 |
|---|---|---|
| `xiaoxiang_library` | `library` | 图书馆介绍与该地点相册 |
| `xiaoxiang_teaching_group` | `teaching` | 统一课表入口、楼座筛选、课表管理与教学楼群相册 |
| `xiaoxiang_sports_ground` | `stadium` | 潇湘校区体育场（副场）的社团活动查询与该地点相册 |

共享声明以 `PlaceIdentity` 联合类型约束这三组对应关系。地点名称、入口位置或标注改动不改变 `placeId`，相册关联不使用名称或坐标作为键。交互标注不重复保存 `name` 或 `featureKey`，通过地点注册表关联，避免地图和功能模块各自维护出不同的名称或功能映射。

每条 `interactions` 记录为：

`{ placeId, verificationStatus, entrancePoint: Point | null, triggerPolygon: Point[] | null, returnFallbackPointId: string | null }`

- `entrancePoint` 保留为地点定位和重叠范围下选择目标的参考点，不是必须踩中的交互点；用户无需精确踩点或穿过建筑门口。
- `triggerPolygon` 表示建筑或场地周边的可通行交互区域，按角色脚底点是否处于该范围内判定。它不得覆盖不可通行的建筑内部、水面等障碍；角色正常通行仍遵守完整脚底碰撞体检查。范围大小、形状及具体坐标仍为 `pending`，本轮不填坐标。
- `returnFallbackPointId` 引用用途包含 `return` 的安全点，只在保存的原触发位置失效时兜底。
- 记录为 `pending` 或入口/触发范围尚未标定时，正式场景不得据此提供可进入提示。
- 三个地点统一使用已确定的 **E 键**。脚底点处于已核验触发范围内时显示“按 E 进入【地点名称】”，用户按 E 后才请求进入对应功能页；范围外按 E 不触发。
- 一次新的 E 按下只产生一次请求，忽略键盘自动重复事件（`repeat`）。按住 E 再走入范围不会自动打开，必须先松开、再在范围内重新按下 E。功能页、表单及其他输入界面打开时不监听地图交互 E。
- 范围重叠时，A 仅从脚底点所在的有效触发范围中确定一个当前目标，再用同一个 `placeId` 显示提示与发送请求。可采用距离 `entrancePoint` 最近、相同距离按固定 ID 排序的确定性规则，避免提示和打开对象不一致。

### 3.4 安全点

`SafePoint`：

`{ id, position: Point, usage: ('spawn' | 'teleport' | 'return')[], verificationStatus }`

安全点只有核验后才可用于对应用途；同一点可声明多个用途。它必须容纳完整脚底碰撞体，能接入有效道路，不能落在水面、建筑内或无法离开的孤立区域。出生点及快速移动点的数量、位置和开放方式未确认，待标定模板使用空集合，不预先规定每校区一个。

### 3.5 遮挡素材

`Occluder`：

`{ id, imagePath, rect: { x, y, width, height }, depthAnchorY, verificationStatus }`

`rect` 表示该素材在原图坐标中的放置区域，宽高大于零；素材不得因缩放或裁剪丢失与原图的定位关系。`depthAnchorY` 表示用于与角色脚底比较的深度基线，不是建筑图片的顶边。按角色在物体前方或后方选择绘制顺序，并使用透明轮廓处理建筑与树木遮挡。

最终 PNG 已经画有完整建筑和树木。只复制一层透明前景覆盖在上面，不会自动得到干净的物体后方地面，也不能据此宣布完整遮挡已经解决。开发素材必须采用并核验以下适用做法之一：

1. 另建用于游戏渲染的干净底层和透明物体层，保留物体后方可见、可行走地面；最终 PNG 仍原样留存。
2. 对局部采用前景遮挡，并合理限制没有可用后方地面的穿行区域；限制不能破坏三个校区及功能入口的必要连通性。

当前 V1 的 `imagePath` 与哈希仍绑定原样底图，没有另设干净底层替换字段。因此本版可先采用第 2 种办法；若第 1 种办法成为必要条件，由 A 提出明确的素材接入与接口扩展，再交主控统一，不能悄悄替换原样底图或绕过哈希校验。

图中的静态人物和车辆仍是底图内容，不自动成为 NPC、载具或碰撞对象。开发角色和骑行外观另行准备。

## 4. Tiled 接入边界与未来素材路径

> **2026-09-26 实施记录：** v20 的行走区改为由 `tools/map/extract-walkable.mjs` 按底图颜色自动提取，再由 `tools/map/build-annotation.mjs` 转为 `public/maps/campus-v20.annotations.json`（行走区为矩形分解，碰撞区为空——建筑、水面等已直接排除在行走区之外）。颜色无法识别的桥面、门洞等在脚本中以带原因的手工多边形补齐。`annotationStatus` 保持 `pending`，三个交互记录仍为空坐标。Tiled 仍可作为后续精修手段，输出同一份 MapAnnotation。

A 独占地图编辑源、标注转换器和运行时地图适配。其他模块读取共享契约，不各自解析 Tiled，不手改 A 导出的坐标，也不通过功能组件直接修改场景对象。

建议以最终 PNG 为图片图层，在对象图层绘制行走区、碰撞区、地标、交互区域和安全点。编辑网格只是辅助工具，不要求把 PNG 切成瓦片。Tiled 源文件/导出 JSON 是编辑格式，`MapAnnotation` 是应用唯一消费格式；A 负责转换和校验。

为减少歧义，本版编辑约束为正交坐标模式、图片原尺寸、图层偏移为零、对象旋转为零、视差因子为 1；对象仅使用点、矩形、多边形。矩形转为四点多边形；Tiled 多边形局部顶点加上对象位置后才成为原图绝对坐标。转换器发现未支持的变换或图层特性时明确报错，不静默忽略。

Tiled 的地图 `width` / `height` 是瓦片列数/行数，对象 `x` / `y` 才以像素表达。不得把地图行列数写入 `widthPx` / `heightPx`，也不得把多边形局部顶点当作绝对坐标。`orthogonal` 只表示编辑坐标模式，不表示真实地理北朝上。参考：[Tiled 官方 JSON 地图格式](https://doc.mapeditor.org/en/stable/reference/json-map-format/)。

## 5. 地图、宿主与功能页协议

页面跳转统一约定为：在同一应用内，从地图探索页切换到所选地点的独立功能页。宿主保留地图状态并暂停探索，返回时恢复原场景。既有 `Panel`、`PlacePanelProps` 等命名表示功能页组件，不要求使用小弹窗；下文的关闭流程对应退出功能页并返回校园。

### 5.1 打开请求

地图向宿主发送的唯一自定义事件为：

`request-open-place { placeId }`

只有角色脚底点处于有效触发范围、当前交互目标明确且收到一次新的 E 按下时才发送。地图忽略自动重复事件，范围外按 E、按住 E 后进入范围均不发送请求。宿主再次校验三个固定 ID、目标有效性与当前功能页状态；已有功能页时忽略重复打开请求，不叠加第二个地点功能页。

宿主在切换功能页前保存此次按 E 的原触发位置、朝向和地图标识，生成本次 `sessionId`，停止角色移动、清除按键状态并获取唯一输入锁；不把角色移动到 `entrancePoint`。功能页完全结束后才释放锁，不能在点击返回按钮的一刻提前解锁。

### 5.2 功能页组件入参

共享功能页组件入口仍为 `PlacePanelProps`：

| 入参 | 职责 |
|---|---|
| `place` | 当前已校验的地点定义；相册始终绑定它的固定地点 ID |
| `sessionId` | 本次打开会话标识，用于识别迟到回调，防止旧功能页异步结果影响新功能页 |
| `buildings` | A 提供的只读楼座目录，类型为 `readonly Building[]`；未核验时为空，教学楼模块不能自行编造条目 |
| `onRequestClose` | 请求宿主退出功能页并返回校园；页面不能自行恢复角色输入或直接移除场景锁 |
| `onLocate` | 请求宿主标记地图目标；返回明确定位结果，不瞬移角色 |
| `registerCloseGuard` | 登记并在适当时机解除关闭检查，用于未保存编辑或未结束写入；具体函数签名以共享声明为准 |

各功能模块仅通过这些回调与宿主协作，不直接访问或修改 Phaser 场景、镜头、角色、按键或碰撞体。关闭检查未通过时功能页和输入锁继续保留；关闭检查通过后，宿主退出功能页、恢复室外上下文、清空 WASD/Shift/E 等按键状态，再释放锁。

`CloseGuard` 返回 `true` 表示允许退出功能页，`false` 表示保留功能页；异步检查完成前保持输入锁。注册返回的函数用于注销该检查。存在多个检查时必须全部通过；抛出异常或 Promise 拒绝时保持功能页并提示错误。宿主合并同一会话中的重复关闭请求，忽略已失效 `sessionId` 的迟到结果。

三个地点返回时均优先恢复此次按 E 的原触发位置与朝向，不强制回到 `entrancePoint`。如果原触发位置因地图状态变化已无效，再使用此地点关联、已核验且可用的 `returnFallbackPointId`。没有有效兜底时应明确报错并保持安全状态，不能送到 `(0,0)` 或任意地标中心。

功能页、表单输入、图片选择、相册和大图查看期间保持输入锁，地图不监听 E；浏览器窗口失焦时停止移动并清键。返回校园后需要新的按键输入才恢复操作，避免残留的 Shift、方向键或 E 继续生效；持续按住 E 不得导致刚返回就再次进入功能页。

### 5.3 定位回调

`onLocate(target): Promise<LocateResult>` 接受共享声明定义的三类目标：`place`、`building`、`landmark`，并异步返回以下结果：

| 结果 | 含义 |
|---|---|
| `marked` | 目标存在且具有可用的已核验地图位置，已更新目标标记 |
| `unmapped` | 目标已知，但地图对应关系、位置或位置核验尚缺失 |
| `unknown-target` | 目标类型/ID 无法识别，不属于当前已知对象 |

地点目标使用对应的已核验入口位置；楼座目标通过 `Building.landmarkId` 找到地标锚点；地标目标使用自身已核验 `anchor`。楼座存在但没有 `landmarkId`，或对应锚点尚未标定，均返回 `unmapped`，不能用教学楼群入口冒充具体楼座位置。

定位成功后更新目标标记并在当前地点界面之上显示地图总览；关闭总览后回到原地点界面。定位不关闭地点会话、不打开其他地点功能、不改变角色位置，也不执行快速移动。总览或地点界面任一层仍打开时，宿主持续保留输入锁。`unmapped` 或 `unknown-target` 时显示对应说明，不放置虚假标记。总览和搜索沿用同一定位边界，不能绕过到达地点与主动互动的要求。

## 6. 标定步骤与状态推进

1. **锁定底图。** 核对尺寸和哈希，以原尺寸放入编辑场景；保留最终文件，建立开发素材来源记录。
2. **分开记录地理证据。** 核验三校区、主要道路、重点地标、教学楼座，以及体育场（副场）的现实位置与道路关系；冲突保留待核验，不依靠图片中的箭头解决现实方位问题。地理核验不重新决定已确认的交互场地选择。
3. **标出必要通路。** 先覆盖三校区之间与三个功能入口之间的主通路，再补需要开放的支路。明确桥面和水域关系，记录脚底碰撞体尺寸。
4. **补齐障碍与遮挡。** 标记建筑、水面等阻挡区，制作必要的分层素材，验证人物在树木/建筑前后及桥头位置的表现。
5. **标定地标、楼座和入口。** 保持固定 ID，补齐真实对象对应关系，再录入锚点、入口和触发区域；操场交互仅标定体育场（副场），入口位置和触发范围经检查后才转为有效标注，不为鸟巢或其他运动场增设功能入口。
6. **标定出生及安全点。** 在数量、位置与开放方式决定后录入，检查脚底碰撞体净空、接路和返回兜底引用。
7. **导出并检查。** A 转换成 `MapAnnotation`，检查坐标、几何、ID、引用、图片哈希、三个交互目标、道路连通和遮挡素材。
8. **分别推进状态。** 标注可用性、地理核验和应用验收分别留记录，满足各自条件后才修改对应状态。

`annotationStatus: 'verified'` 表示当前整份标注已完成可用性核验：所需行走区/碰撞、三个入口、安全点、引用和适用遮挡均有记录。它不表示应用功能已经实现或浏览器验收通过。`geographyStatus: 'verified'` 需要现实地理核验记录，不能由标注检查或游戏能走通自动获得。

单个 `verificationStatus` 只确认对应记录，不能代替整图状态。局部标注可以供开发调试使用，但整图仍为 `pending` 时须明确显示未完成边界，不能作为正式探索已验收成果。

标定前可并行完成：三个地点的功能和相册关联、面板协议、输入锁和关闭流程、课表/社团活动/相册接口、空状态和失败处理，以及独立测试场景中的移动、碰撞和坐标转换验证。正式地图路线耗时、速度倍率、出生和快速移动策略要待相关参数明确后验收。
