## 本次确定的技术基线

| 层 | 采用方案 | 责任 |
|---|---|---|
| 场景 | Phaser；角色、镜头、碰撞、遮挡、地点提示 | A |
| 界面 | React + TypeScript + Vite；各地点界面和本地编辑器 | A 建公共框架，B/C/D 开发功能 |
| 地图标注 | Tiled 图片层与对象层，经 A 的适配器输出本项目 MapAnnotation JSON | A |
| 本机服务 | Node.js 24 LTS + Fastify + multipart 上传 | D |
| 个人课表 | 当前浏览器 IndexedDB；不提供课表 HTTP 写入接口 | B |
| 公共内容 | 本机 JSON 快照，只有 D 的服务负责落盘 | C 编辑，D 保存 |
| 地点相册 | 本机图片文件 + JSON 索引，共用 React 相册组件 | D，B/C 复用 |
| CSV | Papa Parse 负责文件语法解析，B 负责课程含义校验 | B |
| 验证 | Vitest 用于逻辑和适配验证，Playwright 用于浏览器流程；地理和画面另外检查 | 各工作线与 A |

这是完整应用的实施约定。初始只读检查得到 Node.js `v24.19.0`、npm `11.17.0`。后续地图预览阶段已创建 package.json 和锁文件并安装前端依赖；项目仍未初始化 Git，本机数据服务尚未实现。

地图预览阶段已核对官方 React/TypeScript 模板，将 Phaser 固定为 `4.0.0`，实际依赖由根 package.json 和 lockfile 统一维护，其他工作线不分别升级。现有旧版 Phaser 示例需要与实际锁定版本核对，不能直接混用。

## 三个固定地点 ID

| placeId | 显示名称 | featureKey | 功能责任 |
|---|---|---|---|
| `xiaoxiang_library` | 潇湘校区图书馆 | `library` | D |
| `xiaoxiang_teaching_group` | 潇湘校区教学楼群 | `teaching` | B |
| `xiaoxiang_sports_ground` | 潇湘校区体育场（副场） | `stadium` | C |

以上 ID 自接口版本 1.0.0 起固定。显示名称和地图位置可以修改，身份不随之改变。楼座编号 `buildingId` 与交互地点 `placeId` 分开；教学楼群始终只有一个交互入口和一个相册。

2026-09-26 场地确认修订：操场确定为体育场（副场）；接口字段、地点 ID、路由和相册归属不变，接口版本仍为 1.0.0。

统一操作已确认：靠近地点并进入互动范围 → 显示“按 E 进入【地点名称】” → 按 E 跳转对应功能页面 → 返回校园时恢复原触发位置。无需精确踩中入口参考点；区域的大小和边界仍待标定。技术上采用同一应用内切换功能页面，保留地图会话；现有 Panel 类型与回调继续用于页面接入，不要求做成小弹窗。

## 运行与数据边界

- 开发时固定通过 `http://127.0.0.1:5173` 访问 Vite，`/api` 代理到只监听 `127.0.0.1:8787` 的本机服务。
- 本机验收构建由服务在 `127.0.0.1:5173` 提供静态页面与 API；先停开发前端。不得端口被占用后静默改号。
- 若用户以后修改入口地址或端口，应提示先导出个人课表；浏览器存储按来源隔离，不能把换地址当作课表损坏。
- 相册和公共内容保存在项目 `data/` 下，独立于 `dist/` 和 `public/`；构建不得覆盖用户数据。开发 worktree 使用各自的测试数据目录。
- 前端地图预览已可按根 README 启动。上述本机服务、API 代理和数据保存规则仍为未来实现约定，不表示已启动服务或通过持久化验收。
