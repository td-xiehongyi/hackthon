# 角色移动恢复排查

日期：2026-09-27

## 已确认的触发路径

鼠标在地图中拖动超过 4 像素，就会切换到自由浏览。旧逻辑在自由浏览期间暂停移动按键，只能通过定位按钮回到角色；返回首页后重新进入也可能保留自由浏览状态。因此，一次很轻的拖动即可让角色看起来突然无法移动。

修复前，浏览器测试已复现两种情况：拖动后按 WASD 不移动；拖动后返回首页、重新进入并打开关闭全图，按 WASD 仍不移动。

## 修复后的操作

- 松开鼠标后，新按一次 WASD，即恢复角色跟随并开始移动，保留当前缩放。
- 自由浏览状态显示“按 WASD 继续行走”的提示。
- 定位按钮继续支持回到角色并恢复默认缩放。
- 拖动尚未结束、建筑界面或全图打开、警察拦停时，不通过 WASD 提前解除暂停。
- 输入文字、输入法组合输入、Ctrl/Alt/Meta 组合键或旧按键的自动重复，不触发自由浏览恢复。

## 验证

- 构建与类型检查通过。
- 54 项单元测试通过：移动输入、移动计算、建筑会话、南门提醒。
- 23 项浏览器检查通过：新增移动恢复场景，以及地图覆盖层、缩放、建筑互动和警察拦停回归。
- 五类建筑分别连续三次进入地点相册并返回，再打开关闭全图后，均验证角色坐标能够变化。
- 验证失焦清空按键、新按键恢复移动；自由浏览恢复不会改变缩放；拖动中、全图内及文字输入期间不会提前恢复。

相关测试：`tests/e2e/movement-recovery.spec.ts`。浏览器结果分别位于 `output/movement-recovery-checks`（21 项）和 `output/movement-recovery-guards`（2 项）。

## 结论边界

这是一条已复现并修复的确定路径。用户反馈没有明显规律，尚不能断言所有偶发停住都由此引起。本次未在反复进出相册、失焦恢复和警察放行的测试路径中复现其他卡住问题。
