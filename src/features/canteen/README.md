# 二食堂窗口浏览

## 体验入口

进入校园后，走到地图中部麓南校区的二食堂南侧。建筑高亮并出现提示时按 E，打开二食堂页面。

- 选择 1–4 楼，每层两个示例窗口，各有名称和独立插画。
- 点击窗口查看评分与评价；返回窗口列表时保留当前楼层。
- 在详情页切换楼层会退出旧窗口详情，避免显示上一层的评价。
- 返回校园恢复进入时的角色位置与朝向，重新进入默认显示 1 楼。
- 无评价时显示“暂无评价 / 暂无评分”；图片加载失败时显示“窗口图片待补充”。

## 资料来源与替换

用户已确认先做示例体验版。当前名称、楼层分布、图片和预置评价均为演示内容，不代表二食堂真实窗口或学生反馈。预置评价有示例标识；用户发布的评价单独展示，按窗口保存。

目录集中在 `data.ts` 的 `CANTEEN_FLOORS`，图片位于 `public/canteen/`。

正式资料到位后，按 `level` 更新各层的 `windows`，每个窗口填写 `name`、`specialty`、`image` 与 `reviews`。`image` 使用可访问的站内路径；窗口与评价的 `id` 保持唯一且稳定。没有实际评价时保留空数组，不编造评分。替换完全部示例后再调整页面上的示例提示。

## 发布与保存评价

窗口详情中的“写评价”可填写 1–5 分、选填昵称及 1–1000 字评价。昵称为空时显示“匿名同学”。发布成功后显示确认提示，并更新当前窗口的评分和评价数；存在用户评价时，评分只计算用户评价，预置示例不参与混算。

已发布评价通过本机数据服务保存在 `data/canteen-reviews.json`；若配置了 `CAMPUS_DATA_ROOT`，则保存在该数据目录。同一服务下，刷新页面、关闭后重开或重启服务后都可读取；不依赖浏览器缓存。数据未上传到外部服务，不提供账号认证或跨电脑云同步。

发布接口为 `POST /api/v1/canteen/reviews`，读取接口为 `GET /api/v1/canteen/reviews`。服务验证窗口、评分和长度，追加时通过同目录临时文件原子替换；提交 ID 相同时重试不重复保存。已有评价文件损坏时明确报错，不会重置或覆盖为空。

切换楼层和窗口时，未发布草稿暂存在当前食堂页面中；离开食堂或刷新有未保存提醒。保存失败保留表单，重试使用同一提交 ID。草稿尚未发布时不属于已持久保存的评价。

更新代码后需重启本机数据服务以加载新接口；前端仍使用原启动地址。备份评价时保留对应数据目录中的 `canteen-reviews.json`。构建产物不包含该数据文件，测试使用独立临时目录。

## 地图接线

- 地点 ID：`lunan_canteen_2`；功能：`canteen`；校区：`lunan`。
- 入口参考点：原图 `(560, 748)`；触发区域覆盖建筑南侧 `(485, 720)` 至 `(635, 776)`。
- `public/maps/campus-v20.annotations.json` 保留原通行区域和三个既有地点，仅追加食堂交互与建筑高亮轮廓。
- 入口可站立与游戏交互已验证；现实位置与建筑入口的地理核验仍为 `pending`。
- 面板复用 `PlaceHost` 的会话、地图暂停和原位返回；不直接操作场景。

## 检查

`tests/unit/canteen-interaction.test.ts` 验证校区身份、入口可站立、范围内触发和范围外取消。

`tests/e2e/canteen.spec.ts` 验证四层浏览、图片加载、评价对应、详情切层、空评价、键盘焦点、地图暂停与原位返回，以及 390px 窄屏和图片失效状态。

`tests/unit/canteen-reviews.test.ts` 验证落盘后新服务读取、追加保留、幂等重试、输入与来源校验和损坏文件保护。`tests/e2e/canteen-reviews.spec.ts` 验证发布、刷新、新浏览器上下文读取、窗口隔离、窄屏、加载失败重试以及保存响应丢失后的重试。
